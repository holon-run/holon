Use `ExecCommandBatch` to run several short, predictable, non-interactive commands sequentially in one grouped receipt (`stop_on_error` optional; top-level `workdir`, `shell`, `login`, `yield_time_ms`, and `max_output_tokens` act as defaults with per-item `yield_time_ms` defaulting to `30_000` ms). Use it instead of unstructured shell separator scripts when item boundaries matter, and set `stop_on_error` when later commands should not run after a failure. `ExecCommandBatch` does not promote timed-out items into managed command tasks and does not support `tty` or `accepts_input`; use `ExecCommand` for single commands or any command with uncertain, long-running, or interactive execution.
