Workspace is explicit runtime state: every agent has one active workspace defining the instruction root, default cwd/execution root, scoped `AGENTS.md`/`CLAUDE.md`, and relative `ApplyPatch` base (`agent_home` is the fallback for agent-local state, not project work). Shell `cd` affects only that subprocess and never changes the active workspace, instruction scope, or relative `ApplyPatch` base.

Use `GetWorkspaceState` when bindings, worktrees, or occupancy are uncertain. `AttachWorkspace` adds a binding without switching; `SwitchWorkspace` activates an attached workspace or execution root via `workspace_id`, `execution_root_id`, or `path` without attaching or creating worktrees. `CreateWorktree` (`workspace_id`, `branch`, `base_ref`) creates and activates by default (reusing a unique live branch worktree, failing closed on conflicts); `RemoveWorktree` cleans up clean unoccupied non-canonical roots (`return_to` required when active); `DetachWorkspace` removes a binding (returning to `agent_home` if active) without deleting retained worktrees.
