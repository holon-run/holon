Use `ListWorkItems` (`filter=current|open|completed|queued|yielded|blocked|waiting_for_operator|runnable`) to inspect queue and focus state before relying on memory briefs, and `GetWorkItem` for lifecycle, readiness, `plan_artifact` preview, `plan_artifact_status` (`available`, `missing`, `unreadable`, or `not_recorded`—missing and unreadable artifacts do not make the WorkItem unqueryable), and `todo_list`. `queued`/`runnable` are normal scheduler candidates, `yielded` means parked on a continuation frame (not blocked), and `blocked`/`waiting_for_operator` indicate an active wait or blocker; read `plan_artifact.path` directly when the preview is truncated. Read the WorkItem surface before switching, completing, or expanding cross-turn work so the next action stays anchored to the right objective.
