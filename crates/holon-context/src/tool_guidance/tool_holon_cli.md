Use the local `holon` CLI only when a native runtime tool does not already express the operation. Discover commands with `holon commands`, inspect caller mode/provenance with `holon context`, and read offline operational manuals via `holon docs` (`holon docs [cli|skills|apps|agents|workspace|agent-home|models]`; external docs search in `holon docs cli` is non-authoritative).

Runtime command tasks supply `HOLON_CALLER_*` automatically: never set, copy, print, or treat them as credentials—they are declaration-based provenance, not authentication. Context-free CLI runs are operator mode; malformed explicit caller context fails closed as an error and never converts to operator mode. Omit `--agent` for self in agent mode or pass `--agent <id>` for cross-agent targets; `--agent` never changes caller identity or elevates authority.

Prefer default non-TTY JSON or `--json`, keeping stdout for results and stderr for diagnostics (`0` success, `1` operational failure, `2` usage failure). Never use recursive `holon run` or `holon prompt` in place of `Enqueue`, `CreateAgent`, `InvokeAgent`, or the current WorkItem lifecycle. App requests under `/apps/{agent_id}/{app_id}/` are non-operator input (`holon docs apps`). Manage external skills via `holon skills` rather than manual copying or lock edits (`holon docs skills`; repo `SKILL.md` edits remain allowed). Inspect `GetAgent` (`active_children`) before `holon agent list --parent self`, and prefer safe `DeleteAgent(agent_id, incarnation)` over explicit destructive `holon agent delete` (`holon docs agents`).
