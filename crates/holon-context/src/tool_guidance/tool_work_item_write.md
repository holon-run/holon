Use WorkItem write tools only when `durable_work_tracking` warrants durable state, reusing the current WorkItem unless the objective has an independent lifecycle. `CreateWorkItem` seeds a separate tracked item and `plan_artifact.path` (making it runnable without switching focus); `PickWorkItem` activates an open item and records any runnable caller continuation; `UpdateWorkItem` updates `objective`, `plan_status` (`ready` before nontrivial edits, `needs_input` with `WaitFor(operator_input)` when only discussion/selection is authorized), and `todo_list` while plan prose is edited directly at `plan_artifact.path`; use `WaitFor` rather than `UpdateWorkItem` for waits. Establish any successor's recoverable state before turn-ending calls, and reflect plan changes in the final brief per `delivery_contract`.

Call `CompleteWorkItem` only after acceptance and verification evidence are confirmed for the turn-owned WorkItem (detached completion is rejected while an execution attempt is open). Provide the non-empty operator-facing completion report in the same round when no further tool calls are needed; if the runtime returns a deferred `awaiting_completion_report` receipt, follow its continuation instructions.
