Use WaitFor when progress is intentionally paused until a specific wake condition: `wake=task_result` with `resource` set to the task id, `wake=timer` with `resource` set to a real timer id returned by `CreateTimer` or `ListTimers`, `wake=system` for the next non-work-queue system wake, `wake=external` with `resource` set to a stable outside object such as a URL or `github:owner/repo#123`, or `wake=operator_input` when only the operator can unblock the work. Do not use a natural-language timer description as `resource`; invalid, foreign, cancelled, or already-consumed timer ids return a recoverable tool error. Always provide a concrete `reason`. Optional `recheck_after_ms` records a timed fallback recheck.

Every call must explicitly choose `delivery=final` or `delivery=silent`. Use `final` when yielding needs a non-empty operator-facing final report. The runtime first classifies the outcome: `continue_turn` requires no waiting report, even with `delivery=final`. Only an `awaiting_final_report` receipt opens a pending-report continuation; then use only the exposed read-only fact-checking tools before producing final text, and never call `WaitFor`, `CompleteWorkItem`, or another lifecycle-control tool recursively. If report-time revalidation returns `continue_turn`, the report restriction ends. Use `silent` when no user-facing brief is needed; yielding settles without another report round. The runtime commits the selected delivery, wait, successful tool evidence, turn terminal, and queue terminal atomically.

Wait ownership resolves from the execution-bound WorkItem first; a conflicting explicit `work_item_id` is ignored and disclosed in the receipt instead of failing. Without an execution binding, the wait resolves from an explicit owned open `work_item_id`, then the turn-bound WorkItem, then current focus; if none exists, the wait belongs to the agent lifecycle. Focus is only a fallback and does not change an existing execution or task owner. A task-result wait must belong to the same agent as the task, but any WorkItem of that agent may hold the wait: the recorded waiter is paused and resumed, while the task's captured owner never changes and is never migrated by an explicit `work_item_id`, CreateWorkItem, or PickWorkItem. A task created without any WorkItem owner can be awaited at agent-lifecycle scope without first creating or picking a WorkItem.

Follow `result.continuation`: `continue_turn` means continue useful work in this same turn without waiting again for that result; `yield_and_wait` means yield until the registered wake arrives; `yield_and_reenter` means yield for the exact queued task result to reenter the model. Already-consumed results and results claimed by another waiter return `continue_turn` without a new wait or duplicate wake. Do not assume every successful WaitFor ends the turn. If task state, execution binding, WorkItem revision, or wake state changes before settlement, the runtime rejects the stale prepared wait rather than publishing an obsolete final report. Do not use UpdateWorkItem blocked fields for new waits.
