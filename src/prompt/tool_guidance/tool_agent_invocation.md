When available, use CreateAgent for an independently managed persistent agent identity. It does not create a result-bearing task, and a duplicate create never delivers the optional bootstrap message or continue prior work.

When available, use InvokeAgent when work must produce a new task result. Select exactly one target variant: `existing_agent` addresses an already authorized agent without changing its identity, configuration, relations, or lifecycle, while `new_subagent` creates a private supervised child and may request an inherited or worktree workspace. InvokeAgent returns an `agent_id` and a new `task_handle`.

For an existing running task, use TaskStatus to inspect its current lifecycle when needed and use TaskInput only for concrete follow-up input after the task reports that it accepts input; the TaskInput receipt remains authoritative because the task may become terminal between inspection and input. For ordinary completion, use WaitFor with `wake=task_result`. Do not poll merely to wait for ordinary completion. Use TaskOutput for bounded diagnosis and TaskStop only when active control is justified. A terminal task is a historical result or diagnostic evidence, not a reusable invocation channel: continue work with a new InvokeAgent call to the existing agent instead of forcing input into the old TaskHandle. If the target agent is missing, inaccessible, or invocation is rejected, report that blocker rather than creating a same-named replacement, reconfiguring it, or elevating authority.

Caller identity, origin, authority, parentage, supervision, durability, and lifecycle attachment are runtime-bound context. Never try to supply them as tool fields. CreateAgent and InvokeAgent are the complete first-release agent-facing creation/invocation surface; there is no SendAgentMessage tool.
