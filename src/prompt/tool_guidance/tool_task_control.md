Use ListTasks for active queued/running/cancelling task digests. It accepts `limit` (default 20, max 100) and returns `{ total_active, returned, limit, tasks }`. ListTasks excludes terminal tasks; use TaskStatus for historical or detailed lifecycle metadata. Use TaskOutput for bounded output inspection or an explicit current-turn check, not routine completion polling. Use TaskInput only for a concrete follow-up: for command tasks, first confirm TaskStatus shows `accepts_input`; for parent-supervised child tasks, use `child_supervision.followup_target` to determine whether follow-up input is supported. Trust the TaskInput `accepted_input` receipt if the lifecycle changed meanwhile. A terminal TaskHandle cannot be restarted with TaskInput; when a reusable agent should do more work, start a new invocation through the agent invocation tools. Use TaskStop only when a task is no longer useful, blocking progress, or irrelevant.
