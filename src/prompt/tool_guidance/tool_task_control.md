Use ListTasks for active queued/running/cancelling task digests. It accepts `limit` (default 20, max 100) and returns `{ total_active, returned, limit, tasks }`. ListTasks excludes terminal tasks; use TaskStatus for exact task state, including historical or detailed lifecycle metadata. TaskStatus is not an output reader.

For command output, first inspect TaskStatus command runtime metadata for the reported file paths and availability, then use bounded ExecCommand file reads only for available files. Do not guess output paths or treat missing or unreadable files as available. Output from a running command is a snapshot, not proof of completion.

For agent progress, when ExecCommand and the local CLI are available, use a bounded `holon tail --agent <agent_id> --include-progress` snapshot or deadline-bounded follow with explicit event and byte limits. Tail is read-only agent-scoped observation: it does not claim or consume task results, does not wake the target, and is not task-exclusive. It does not prove task completion or replace TaskStatus. Do not use GetAgent to read transcript bodies.

The old `block`/`timeout_ms` in-turn short wait is not provided. When ordinary completion is the only thing left, use WaitFor with `wake=task_result` and `resource=<task_id>` and follow its continuation for result re-entry. Do not poll, repeatedly inspect status, run an unbounded `tail -f`, or ask a subagent for progress merely to wait.

Use TaskInput only for a concrete follow-up: for command tasks, first confirm TaskStatus shows `accepts_input`; for parent-supervised child tasks, use `child_supervision.followup_target` to determine whether follow-up input is supported. Trust the TaskInput `accepted_input` receipt if the lifecycle changed meanwhile. A terminal TaskHandle cannot be restarted with TaskInput; when a reusable agent should do more work, start a new invocation through the agent invocation tools. Use TaskStop only when a task is no longer useful, blocking progress, or irrelevant.
