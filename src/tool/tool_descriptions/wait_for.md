Record an explicit wait condition or resolve an already available task result. Follow result.continuation: continue_turn means continue useful work in this same turn (no wait or final report is needed); yield_and_wait means yield until the wake arrives; yield_and_reenter means yield for the exact queued task result to reenter the model. Already-consumed results and results claimed by another waiter return continue_turn without registering a duplicate wait. Every call must choose delivery=final or delivery=silent. Use final when yielding must publish a non-empty operator-facing assistant final; only yielding paths request that report. If the runtime opens a pending-report continuation, follow the restricted continuation contract below. Use silent when no operator-facing brief is needed; yielding settles without another report round. The selected delivery, wait registration, tool evidence, turn terminal, and queue terminal are committed together, so a stale task, execution binding, WorkItem revision, wake, or interjection cannot publish an obsolete waiting report. Use wake=task_result with resource=<task_id> when waiting for a background task. For every wake kind the waiter is the current execution-bound WorkItem when one exists; a conflicting explicit work_item_id is ignored and disclosed in the receipt instead of failing. Without an execution binding, optional work_item_id explicitly selects an open WorkItem owned by this agent, then the turn-bound WorkItem, then current focus; if none exists it records an agent-lifecycle wait. The task may belong to any WorkItem of this agent (tasks of other agents are rejected); waiting never migrates the task or changes its owner. Optional recheck_after_ms records a fallback recheck deadline.

Before calling `WaitFor(delivery=final)`, finish any required queries, verification, and material collection. If the result is `awaiting_final_report`, no wait has committed yet: provide non-empty operator-facing final text. This pending-report continuation may use read-only fact-checking tools, but do not call `WaitFor`, `CompleteWorkItem`, or another lifecycle-control tool recursively. Use any tool results first, then provide the final report as text. If revalidation instead returns `continue_turn`, the report restriction ends and useful work should continue in the same turn. For `wake=timer`, `resource` must be the real `timer_id` returned by `CreateTimer` or listed by `ListTimers`, not a natural-language description. The timer must belong to this agent and still have an available wake; invalid timer resources are returned as recoverable tool errors with a recovery hint. For other wake kinds, use `wake=external` with optional `resource=<external object such as a URL or github:owner/repo#id>` when waiting for outside state, or `wake=operator_input` when only the operator can unblock the work.
