# Projection Eval Fixtures

This directory holds the minimal deterministic projection-eval adapter fixtures.

- `benchmark/run.mjs projection-eval --suite <json>` runs shell commands for the same case input, captures their stdout JSON manifests, and scores them with `evaluator.mjs`.
- The evaluator only compares machine-readable manifests plus hard assertions from the suite.
- There is no model judge in this flow.
- For real model evaluation, rerun the baseline/candidate models separately and capture fresh manifests; this fixture path is only the adapter and scoring harness.
- `holon debug prompt --manifest` outputs canonical `ProjectionManifest` JSON from the real runtime/debug prompt assembly path. Use `--budget <tokens>` to override the prompt budget.

Fixture layout:

- `fixtures/suite.json`: example suite for tests
- `fixtures/mock-runner.mjs`: pure Node command used by tests
- `fixtures/inputs/*.json`: per-case inputs consumed by the mock runner
- `corpus/cases.json`: frozen Phase 0 durable-fact scenario matrix
- `corpus/rubric.json`: hard assertions, thresholds, and diagnostic-only metrics
- `baseline/legacy-phase-0-scorecard.json`: frozen legacy projector observation matrix with per-manifest SHA-256 hashes and invariant results
- `baseline/manifests/*.json`: 36 frozen legacy baseline manifests (12 cases x 3 budgets)
- `candidate-phase-1/scorecard.json`: owner-identity-only candidate comparison
  against the Phase 0 baseline
- `candidate-phase-1/manifests/*.json`: 36 Phase 1 manifests with typed
  WorkItem, Conversation, and AgentLifecycle owner metadata

The Rust legacy projector exports the shared manifest through
`EffectivePrompt::projection_manifest()`. The committed baseline freezes the
corpus and budget matrix; per-activation manifest artifacts are generated by
the debug/fixture command used by a suite.

## Frozen Baseline

The frozen baseline manifests are generated by `src/projection_eval/baseline.rs`
using the real `manifest_from_effective_prompt` code path. Each manifest is
canonical JSON with a trailing newline and is byte-stable across serialization
round-trips and restart reconstruction.

To regenerate the frozen manifests and scorecard:

```sh
REGEN_BASELINE=1 cargo test --lib projection_eval::baseline::tests::regenerate_frozen_manifests -- --nocapture
REGEN_BASELINE=1 cargo test --lib projection_eval::baseline::tests::regenerate_scorecard -- --nocapture
```

Normal test runs verify byte-stability, restart equivalence, budget monotonicity,
and schema/fixture drift against the committed manifests.

## Phase 1 Candidate

Phase 1 changes admission and durable owner metadata without changing rendered
provider sections. The candidate scorecard compares section order,
representation, token allocation, rendered character counts, and content hashes
against the Phase 0 baseline.

The committed scorecard intentionally retains owner-invariant failures where the
legacy projector selects evidence from another owner at large budgets. Those
failures are Phase 2 semantic-projection evidence, not a reason to hide or
rewrite the Phase 1 observation.

To regenerate the Phase 1 candidate manifests and scorecard:

```sh
REGEN_PHASE1_CANDIDATE=1 cargo test --lib projection_eval::baseline::tests::regenerate_phase_1_candidate -- --nocapture
```
