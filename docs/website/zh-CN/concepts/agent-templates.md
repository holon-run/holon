# Agent 模板

Agent 模板为新 Agent 提供初始角色契约，并可选择为其安装依赖的 Skill。当你想让多个 Agent 具备一致的职责起点（例如代码审查）时，可以使用模板。对于简单的一次性提问，使用默认 Agent 往往就足够了。

## 从模板到 Agent

模板库提供可供选择的复用模板。安装或同步模板只是将其纳入模板库，并不会创建 Agent。使用选定模板创建 Agent 时，系统会初始化一个独立的 Agent Home。

例如，`code-reviewer` 可以是模板名称，而 `payments-reviewer` 是具体的 Agent ID。模板名称决定选用哪些初始素材，Agent ID 则对应拥有独立指引、记忆与工作状态的实际工作实体。

未指定模板时，Holon 会使用内置的默认初始化逻辑。模板目录中的具名模板在选择前必须先安装到位；内置默认项的存在并不代表全部模板已提前就绪。

## 角色、工作流与执行

以代码审查为例，四类对象之间的分工如下：

| 对象 | 在审查任务中的职责 |
|---|---|
| 模板 | 提供审查角色的初始契约与可选的 Skill 依赖。 |
| Agent | 承载审查对话、工作记录，并最终产出报告。 |
| Skill | 描述如何排查改动并输出有证据支撑的结论。 |
| 工具（Tool） | 读取 diff、执行检查命令或发送授权消息。 |

模板中的 `AGENTS.md` 会成为该 Agent 的角色指引。可选的 Skill 清单声明初始化期间需要安装的依赖项。这些依赖可能需要网络访问或本地源码文件。成功选择模板并不等于自动获得模型服务商凭据、私有仓库访问权限或发布审查意见的权限。

审查模板虽然描述了评审与批准的工作流程，但不会自动为每个具体任务授权审批。当前请求与运行时安全策略仍然决定着 Agent 的实际权限。

## 模板更新与已有 Agent

角色契约只是创建时刻的起点。更新或同步模板库中的模板，并不会改写已有 Agent 的角色文件；重命名模板也不会改变现有 Agent ID。为了避免覆盖已有状态，Holon 禁止在非空的 Agent Home 上直接套用模板进行初始化。

如果要调整 `payments-reviewer`，应当直接编辑其角色指引并按需管理其启用的 Skill。如果要验证修改后的模板，可以新建一个干净的 Agent，核对生成的指引与 Skill 可用性。

Skill 拥有独立的更新与启用生命周期。以链接方式安装的 Skill 会跟随上游源文件变动，即使 Agent 复制的角色契约未曾改变。不要认为与模板相关的内容要么永久冻结、要么全部跟随模板库更新。详见 [Skill 与工具](./skills-and-tools.md)。

## 选择模板

应根据预期职责与执行边界来挑选模板，并仔细审视其角色契约。一个持续等待外部事件的维护类模板，与一次性解决问题的任务模板有着截然不同的运行假设。贴切的名称或预装的 Skill，都不能替代对这些假设的确认。

[Agent 模板参考](../reference/agent-templates.md)列出了完整目录、选择规则、目录结构以及清单配置格式。如果只是使用已有模板创建 Agent，无需手动修改清单。
