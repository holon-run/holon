# 将复杂任务安全委派给子 Agent 并验收交付

在处理大型工程或复杂业务时，让单个 Agent 串行处理所有事情不仅容易让上下文窗口迅速膨胀，还可能因为耗时的深度代码审计、跨模块排错或长时间测试套件执行而阻塞当前的交互。

在 Holon 中，你可以直接在 Web GUI 或终端对话中，用自然语言吩咐主 Agent 将任务委派给专门的受监督子 Agent（例如代码审查员、质量工程师）。主 Agent 会为主从协作划分清晰的职责边界（继承只读工作区或分配全新 Git Worktree 分支），在子 Agent 执行期间零 Token 等待，并在子 Agent 交付结论后逐项核验，最后安全清理临时运行实例。

父 Agent 始终拥有最终验收责任并向你交付权威简报；子 Agent 的输出是参考证据，而非不可推翻的决定。

## 前置条件

- 正在运行的 Holon 运行时与 [Web GUI](./use-web-gui.md)（默认地址 `http://localhost:8080`）或 CLI 环境。
- 处于活跃状态的主 Agent（例如 `main` 或 `developer`）。
- 目标工作区或代码仓库已挂载到 Agent（参见[在项目工作区与 Git Worktree 中工作](./work-with-workspaces.md)）。
- 拥有可用的 Agent 模板（如 `code-reviewer`、`qa-engineer`、`software-developer` 等系统预置或自定义角色，参见[组织技能与角色](./organize-agent-skills-and-roles.md)）。
- 无需手动编写底层 JSON：操作者只需在对话中用自然语言表达委派意图与约束条件，主 Agent 会自动处理调用与结果归集。

## 操作步骤

### 1. 评估委派时机并明确隔离模式

委派的目标是**提高并发度、隔离上下文与保护代码安全**，而不是盲目拆分任务。遵循以下原则：

- **适合委派的场景**：
  - **独立只读审查**：对当前已提交或未提交的代码进行安全、语法或架构审计，不应干扰主 Agent 当前的编码流程。
  - **耗时测试与诊断**：运行全量集成测试、构建基准测试或长时间的性能分析。
  - **探索性或高风险修改**：尝试某种具有破坏性的重构方案，需要验证可行性但绝不能污染当前工作分支。
- **不建议委派的场景**：
  - 修改两行配置、快速查找某个符号定义、简单的多轮问答。此类任务直接由主 Agent 执行更快且开销最小。

确定委派后，根据任务性质选择工作区模式：

| 工作区模式 | 适用任务 | 隔离特性与安全性 |
| --- | --- | --- |
| **继承工作区（`inherit`）** | 只读代码审查、文件索引构建、静态文档检查 | 子 Agent 共享主工作区的文件视图。**必须严格约定只读**，严禁子 Agent 编辑或保存文件，避免与主 Agent 写冲突。 |
| **独立 Worktree（`worktree`）** | 试验性重构、独立功能开发、跑测试生成临时产物 | 为子 Agent 在独立目录下拉出新的 Git 分支。子 Agent 的修改、编译产物完全隔离在 Worktree 中，主工作区毫发无损。 |

### 2. 在对话中用自然语言下达委派指令

你不需要在对话中手写 `InvokeAgent` 的 JSON 参数。直接在 Web GUI 聊天窗口或终端中输入明确带有**角色、范围、权限与交付格式**的提示词。

#### 场景 A：只读代码审查（继承只读工作区）

> “请启动一个 `code-reviewer` 子 Agent，审查 `src/runtime/` 目录下当前的改动。  
> **要求：** 严格只读，禁止编辑、提交或推送任何代码；重点检查边界条件处理与潜在内存泄漏；逐项列出文件路径、代码行号、严重等级和事实依据。若未发现问题，明确说明已检查的文件范围。”

#### 场景 B：独立分支上的试验性重构与测试（Worktree 隔离）

> “请委派一个 `software-developer` 子 Agent，在全新的独立 Git Worktree 分支中重写 `src/auth/token.rs` 中的过期令牌刷新逻辑。  
> **要求：** 运行单元测试确保全部通过；测试通过后提交到新分支，将改动 Diff 和测试结果简报汇报给我；不要合并到主分支，等待我验收。”

主 Agent 接收到指令后，会自动完成以下调度：
1. 调用系统底层的 `InvokeAgent`，拉起对应的子 Agent 并挂载相应的工作区模式。
2. 主 Agent 注册事件等待（`wake=task_result`），进入挂起状态，不消耗多余 Token。
3. 子 Agent 开始独立分析或编码，你可以在 Web GUI 侧边栏的活跃任务中查看子 Agent 的执行轨迹。

### 3. 多维度核验子 Agent 的交付物

子 Agent 完成任务后，主 Agent 会被系统自动唤醒。主 Agent 在向你汇总结论或采纳修改前，必须按照以下标准进行独立核验：

| 核验维度 | 验收标准与防范风险 |
| --- | --- |
| **目标版本对齐** | 检查子 Agent 审查或修改的代码提交 SHA/分支是否与指示一致，防止审查错版本或基于旧提交修改。 |
| **问题定位与证据** | 审查报告中的每个潜在漏洞或缺陷，必须附带真实的文件路径、精准的代码行号与确切的逻辑因果，拒绝模糊空泛的建议。 |
| **真实性（阴性确认）** | 若子 Agent 回复“未发现问题”，必须要求其明确说明已检查的文件清单与测试覆盖项，防止 Agent 偷懒或空转返回。 |
| **编译与测试真实性** | 若子 Agent 负责代码实现，主 Agent 需核验其提供的测试命令退出状态码与测试输出摘要，确认并非伪造断言。 |
| **决策权与合并边界** | 子 Agent 无权自主决定合并分支或执行生产部署。所有合流与发布决定必须汇总给主 Agent，最终由操作者确认。 |

### 4. 汇总答复与安全清理临时实例

当子 Agent 交付并经过主 Agent 验收后，主 Agent 会向你呈现结构化的综合结果（包括发现的问题列表、修改的文件或生成的测试通过证明）。

在任务闭环后，必须安全回收临时计算与存储资源：

1. **复用或保留**：新创建的子 Agent 属于私有可复用实例，会保持停驻在内存/磁盘中。如果你还需要对它进行二次追问或交接后续任务，可以直接对主 Agent 说：
   > “让刚才的审查子 Agent 进一步核查 `src/runtime/worker.rs` 的改动。”
2. **安全释放与清理**：当工作已彻底闭环、无需保留该子 Agent 时，在对话中通知主 Agent：
   > “审查任务已完成，请安全清理刚才启动的临时子 Agent 和它的临时工作区。”
   - **父级清理责任**：Holon 采用显式的所有权回收机制，只有直接发起委派的主 Agent 才能删除自己名下的子 Agent（防止误删其他系统实例）。
   - **安全阻碍检查**：若子 Agent 仍有正在运行的任务、未提交的脏代码，或其 Worktree 仍被其他进程锁定，系统会拦截删除动作并提示主 Agent 先妥善处理未完成的事项。
   - **自动资源退役**：通过运行时自带的生命周期管理，闲置的子 Agent 进程在超时后会自动退役内存占用，保留必要的状态归档。

## 最佳实践与注意事项

- **不要假设独立 Worktree 会包含未提交的脏改动**：
  当使用 `worktree` 模式启动子 Agent 时，它是在全新的独立 Git 目录下检出指定提交。如果你在主工作区有尚未提交的改动，子 Agent 是看不到的。请在委派前先提交改动，或吩咐主 Agent 将未提交改动生成 Patch 传递给子 Agent。
- **区分“对等 Agent 协作”与“临时子 Agent 委派”**：
  - **子 Agent（Subagent）**：专门拉起执行单次特定任务，生命周期完全受主 Agent 监督，任务结束后由主 Agent 回收。
  - **对等 Agent（Peer Agent）**：如系统中长期运行的 `docs-steward` 或 `code-health-steward`。主 Agent 与它们之间是通过持久化异步消息通信（`SendAgentMessage`），不发生主从附庸或销毁关系。
- **防止过度并发与死锁**：
  不要在没有明确依赖管理的情况下同时启动过多互相竞争相同代码目录写权限的子 Agent。写操作统一采用独立 Worktree 分支隔离，读操作统一约束为只读。

## 常见问题排查

- **子 Agent 提示权限被拒绝或缺少工具**：
  检查该子 Agent 所使用的模板是否配置了对应的技能（Skills）。例如只读审查模板通常不需要文件修改工具，若委派指令强行要求其修改代码，子 Agent 会报错拒绝。
- **主 Agent 迟迟没有汇报结论**：
  子 Agent 可能正在执行耗时的测试或下载依赖。你可以在对话中直接询问主 Agent：“刚才委派的子 Agent 当前在执行什么？是否有阻塞？”，主 Agent 会即时查询子任务的最新快照并向你汇报。
