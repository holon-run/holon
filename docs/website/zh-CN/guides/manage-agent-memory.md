# 管理 Agent 记忆

妥善保存稳定的操作偏好，使其在对话轮次增长或客户端断开连接后依然可用。在依赖历史决策之前，应先从原始数据源中检索验证。记忆属于客观证据与辅助上下文，不能替代当下的明确指令，也不能替代工作项的实时状态。

## 前置条件

选定要更新记忆的目标 Agent。使用运行时返回的真实 Agent Home 路径；下文的 `agent_home` 为逻辑描述名，切勿直接在终端中硬编码复制。项目特有的约定请保存在项目仓库中。

## 1. 明确信息归属位置

| 信息类别 | 保存位置 |
|---|---|
| 稳定的操作者偏好（如默认回复语言、命名前缀） | 该 Agent 的 `memory/operator.md` |
| 关于该 Agent 自身角色或长期运行的稳定事实 | 该 Agent 的 `memory/self.md` |
| 常驻职责、权限边界与升级触发规则 | 该 Agent 的 `AGENTS.md` |
| 特定代码仓库的构建命令与本地贡献规范 | 项目工作区的 `AGENTS.md` |
| 正在进行的工作目标、执行计划与待办事项 | 运行时工作项（WorkItem） |

## 2. 更新精选记忆文件

打开该 Agent 的 `memory/operator.md`，记录稳定的偏好项：

```markdown
# 操作者偏好

- 默认使用中文进行回复。
- 在提交 PR 前，必须在本地完整运行并确认测试通过。
```

打开 `memory/self.md`，记录关于该 Agent 自身的持久事实：

```markdown
# 自身事实

- 本 Agent 负责文档翻译与润色工作流。
- 遵循先英文润色、后中文翻译、再中文润色的标准工序。
```

系统会自动将这两个文件的紧凑切片载入上下文；超出预算的部分依然可以通过搜索工具检索到。

## 3. 检索与核验历史记忆

当需要确认过去的决策原由时，引导 Agent 使用检索工具定位证据：

```bash
# 在终端中也可以通过 CLI 查看 Agent 的记忆记录
holon agent get reviewer --detail full
```

在模型调用层面，Agent 会调用 `MemorySearch` 查找关键字，再调用 `MemoryGet` 获取受限的证据详情。切勿单凭模糊的历史摘录就认定某项高风险操作已获批准。
